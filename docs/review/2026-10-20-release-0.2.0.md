# 0.2.0 の検討と作業の記録（2026-10-20）

Inari MCP for Firefox 0.2.0 を決めてから梱包するまでの記録。利用者向けの変更点は [CHANGELOG](../CHANGELOG.md) にあり、ここには判断の理由と検証の結果を残す。

## 1. 前提と方針

- AMO（addons.mozilla.org）の審査に通ることを絶対条件とした。Add-on Policies と Reviewers Guide（Reviewing）を読み直し、次を確認した。
  - 人手で審査済みのアドオンの更新は、前回の承認以降の差分が審査の対象。差分は小さいほどよい。
  - 版は manifest で前回より大きいこと。ソースの提出は前回と同じ（ビルド手順を同梱、依存は公式のパッケージマネージャ経由のみ）。
  - データ送信が変わるときは manifest の `data_collection_permissions` に反映すること。今回の変更は送信するデータを増やさない。
  - アイコンの規定は「わいせつ・憎悪表現・Mozilla の商標の侵害」以外にない。SVG のままでよい。掲載ページのアイコン PNG は Developer Hub で別途差し替える。
  - 「説明どおりに動くこと」。README の対応状況の表と掲載文に新しい操作を書く。
- コードの変更は最低限とし、変更した箇所には `0.2.0:` で始まるコメントを添えて、審査担当者が差分を追えるようにした。
- `chore/post-release-2026-10-19` のうち、コードを触る整理（テスト用の派生クラス、popup の `renderSetup` の分割）は利用者に見えず、審査の差分を増やすだけなので 0.2.0 に入れなかった。docs のコミット（CHANGELOG の節と Release 手順）だけを cherry-pick した。
- 非公開の派生元プロジェクトの名前は、リポジトリの文書とテストのコメントから外し、派生元は ClaudeCodeBrowser（MIT）だけを書くことにした。

## 4. レビュー

独立したレビュー（別モデル、差分 `main..feat/0.2.0` を読み取り専用で）を 1 本回した。

| 区分 | 指摘 | 対応 |
|---|---|---|
| 要修正 | はじめての人向けの手順で「Claude Code 以外は 3 行目の最後に出るコマンドで登録」と書いたが、`--register-claude` 付きでは手登録用のコマンドは出ない（`scripts/install.mjs` の `claudeStep()`） | 「3 行目を `npm run setup` だけにする」に直した |
| 低 | 承認なしの操作の列挙（README の特徴、掲載文の英語）に window が無い | 両方と reviewer-notes に足した |
| 低 | 日本語の掲載文で、伏せる欄の hidden と、MCP クライアントの画面での承認が `api_token` を読める PC 内のプログラムから出せる注意が落ちていた | 戻した |
| 留保 | 掲載文の日本語だけ敬体で、README などの常体と違う | 審査に影響しないので据え置き |

確認済みとされた点：`scope: "tab"` で `needsTabId` を付けない行は `find_text` と同じく、tabId が無ければアクティブなタブに解決する。`fox_set_window_state` は `handlers.ts` の既定規則（`fox_` を外す）で `set_window_state` になり、`ACTION_MAP` への追加は不要。`browser.windows.update` は Firefox では権限を要しない。golden の `guard-decisions` は `switch_tab` と同じく全列 null。

## 5. 検証

| 検証 | 結果 |
|---|---|
| `npm run typecheck` | 0 エラー |
| `npm run lint` | 0 エラー・79 警告（main と同数） |
| `npm test` | 101 ファイル、2153 pass・3 skip、終了コード 0 |
| `npm run test:firefox` | 111 pass、終了コード 0 |
| `npm run smoke:reviewer -- --headless` | 1 PASS・2 SKIP（承認が要る項目は headless では常に SKIP） |
| `npm run pack:ext`（web-ext lint） | 0 エラー・0 警告 |
| `--doctor` の versions | 0.2.0 で 6 か所一致 |

途中で `npm test` の 2 件が落ちていたのを見落とした。`guard.test.ts` の手書きのツール一覧 2 か所（`NOT_PAGE_READS` と handler pipeline の `calls`）が `TOOL_SCHEMAS` を網羅する検査で、`fox_set_window_state` を足していなかった（85c3dea で修正）。見落としの原因は `npm test 2>&1 | grep …` の終了コードが grep のものだったこと。以後はログに落としてから `$?` を見る。

`npm install --package-lock-only` は版の更新のほかに addons-linter 配下の重複を整理して lock を 500 行以上変えた。再現ビルドの前提を崩しかねないので lock は戻し、このリポジトリの 6 項目の版だけ手で変えた。`npm ci` が lock を受け付けることは確認した。

## 7. 見送り・気づき

- lint の警告 79 件（install 70・uninstall 27・processMessage 23 の complexity、extension の complexity 11 が 4 件）。max-params は直さない決定のまま。
- known-issues の未実装（Extension 経路の `fox_snapshot`・`fox_handle_dialog`、`fox_wait` の navigation が完了済みの遷移を拾えない、など）は審査の差分を増やすので今回は触らない。
- README.ja の接続確認の表はポップアップの文言が英語のまま（「Connected」など）。実際の表示は「接続済み」。
- `fox_scroll` の direction 省略時に headless（down）と Extension（何もしない）で挙動が違う。schema に既定値がなく MCP 経路でも観測できる。
