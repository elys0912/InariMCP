# Changelog

**English** | [日本語](./CHANGELOG.ja.md)

User-facing changes of Inari MCP for Firefox, newest first.

Inari MCP for Firefox started on 2026-10-14 as a copy of [KitsuneMCP](https://github.com/elys0912/KitsuneMCP) 0.2.0 (commit b2642a9). It is the edition prepared for listing on addons.mozilla.org: it has a different add-on ID, a different native-messaging host name (`inari_mcp`) and a different state directory (`~/.inari-mcp`), so both editions can be installed side by side. For the history before the split, see the KitsuneMCP changelog.

## Unreleased (0.1.0)

### Added

- First-run permission page: right after installation the extension asks, in a tab, whether Inari MCP for Firefox may connect (what it does, what it sends, what it needs, privacy policy). It does not connect to the native host until you allow it; until then the badge shows `OFF`, and the popup reopens the page. Needs the `storage` permission to remember the answer.
- Pause switch in the toolbar popup: while on, every command from the MCP client is refused with an error starting with `paused`, pending approval requests are withdrawn, and the badge shows `II`.
- The badge shows `●` while a command from the MCP client runs. The badge states have one order: not allowed, paused, approval count, running, setup state.
- README: a Permissions section lists what each of the ten extension permissions is used for and where (`cookies` reads no cookie; it is what Firefox requires to open a tab in a container), and that the agent can create a Firefox container.
- Release tooling for addons.mozilla.org: `npm run pack:ext` builds the Extension zip, writes the SHA-256 of every file in it and runs `web-ext lint` (0 errors and 0 warnings required); `npm run pack:source` makes the source zip from the committed files. [`docs/BUILD.md`](./BUILD.md) tells a reviewer how to rebuild the add-on (Node.js 24, npm 11) and compare it with the submitted one. A GitHub Actions workflow builds, type-checks and tests on Ubuntu 24.04 ARM64.
- Privacy policy: [docs/PRIVACY.md](./PRIVACY.md) ([日本語](./PRIVACY.ja.md)): what is read and sent, where it goes, what stays on your computer and for how long, how to delete it, consent and control, private browsing.
- Material for the addons.mozilla.org listing ([docs/amo/listing.md](./amo/listing.md)) and the Notes for Reviewers ([docs/amo/reviewer-notes.md](./amo/reviewer-notes.md)).
- The toolbar popup always offers the permission page: once allowed, "Withdraw the permission" under the pause switch opens it, and "Don't allow" there disconnects the extension at once.
- `npm run smoke:reviewer` (`scripts/e2e/reviewer-smoke.mjs`) and [docs/amo/reviewer-smoke.md](amo/reviewer-smoke.md): a smoke test of the basic features (tabs, opening a tab, reading with masked fields, find, screenshot, a click, closing the tab; each action approved in the popup) against a local test page on 127.0.0.1, with no Claude Code, account or internet access. `-- --headless` runs it without the extension, where nobody can approve: only the tab list runs. `scripts/e2e/tools-smoke.mjs` uses the same local pages instead of example.com.
- ESLint (including the complexity rules: complexity, max-depth, max-params, max-nested-callbacks, max-lines-per-function, as warnings): `npm run lint:install && npm run lint`. It runs on TypeScript 6 from `tools/lint` (typescript-eslint's peer dependency); the build stays on TypeScript 7. An error fails `npm run lint`, CI and `npm run pack:ext`.
- The add-on package contains `dist/LICENSE`, a copy of the repository's `LICENSE` (the MIT notice of Inari MCP for Firefox and of the project it is based on).

### Changed

- Renamed from KitsuneMCP to Inari MCP for Firefox. Add-on ID `inari-mcp@elys0912.github.io`, host manifest `inari_mcp`, state directory `~/.inari-mcp`, npm packages `@inari-mcp/*`.
- Line endings in the repository are fixed to LF with `.gitattributes`, so the extension built on any OS is byte-identical to the one submitted for review.
- `manifest.json`: `incognito` is `not_allowed` (the extension never sees private-browsing tabs), and `data_collection_permissions` declares `websiteContent`, `browsingActivity` and `websiteActivity` (page content, form values, screenshots and URLs are sent to the local native host and from there to the MCP client, and the extension performs the approved clicks and typing in pages).
- `fox_wait` with `for: "network_idle"`: the counting hooks on the page's `fetch` and `XMLHttpRequest.prototype.send` are installed when the wait starts and removed when it ends (before, they stayed until the page unloaded). They count requests and record nothing about them. Requests already running when the call starts are not seen.
- Screenshots saved under a `filename` you chose are now deleted after `FOX_SCREENSHOT_RETENTION_DAYS` (default 30) like the others; the Native Host lists them in `.named-screenshots` in the screenshots directory and never deletes any other file there.
- README: installation now starts from addons.mozilla.org (1. the extension from AMO, 2. the native host, 3. the MCP client), and the top of the README says what is sent and what is needed. The "WIP", "AMO listing not planned" and "install the unlisted .xpi from GitHub Releases" statements are gone. New sections: Privacy and Links.
- Default ports are `8785` (HTTP) and `8786` (WebSocket) instead of KitsuneMCP's `8765` / `8766`, so Inari MCP and KitsuneMCP can run at the same time. `FOX_HTTP_PORT` / `FOX_WS_PORT` still override them.
- Running Inari MCP needs Node.js 20 or later (`engines`, the installer and `--doctor`); the reproducible build for the AMO review uses Node.js 24.x and npm 11.x.
- A refusal while the agent is paused reaches the MCP client as a safety refusal (`decision: "paused"`, text starting with `paused:`) instead of a browser error.
- The extension's description and the popup footer use the name "Inari MCP for Firefox"; the footer says that page content goes through the native host on this computer to the MCP client.
- The toolbar button, the popup, the badge texts and the context menu use the short name "Inari MCP" (before: "InariMCP"), and so do the approval prompt and the approval notes of the tool results. Approval and CAPTCHA notifications and the popup name the requester "the MCP client" instead of "Claude".
- The permission page lists everything that is sent: page content including the values of form fields (password and similar fields are masked), screenshots, URLs, the tab list and the names of your containers. Its privacy policy link opens the Japanese policy when Firefox's language is Japanese. The popup's pause note says that the command that is running is stopped as well.
- The context menu entry "Take Screenshot for Inari MCP" is there only while the extension is allowed to connect. Before, it was there before the permission and after it was declined too, and its screenshot went nowhere. When the extension is allowed but not connected to the native host, an OS notification now says that the screenshot was not sent.
- The content script runs in the top frame of a page only (`all_frames: false`; no tool reached the other frames), and logs nothing when it loads. No stylesheet is put into pages any more: the overlay of `fox_interact` with `action: "highlight"` gets its look on the element itself, so a page cannot find a class or keyframe name of the add-on.
- Privacy policy, listing and Notes for Reviewers: which calls ask for approval and which do not, that screenshots are not masked, that headless screenshots are not deleted automatically, the files the popup's Screenshot and Page Info buttons make, how `fox_wait` with `for: "network_idle"` wraps the page's `fetch` / XHR, the risk of approving in the MCP client's dialog, and why the `cookies` permission is needed. The listing and the Notes link to the privacy policy of their version tag.
- BUILD.md: four bundles (with `dist/consent/consent.js`), five shared entry points (with `approval-site.ts`) and `dist/LICENSE` in the zip, and the comparison with the submitted add-on leaves out the `META-INF/` folder that AMO's signature adds.
- Every acting tool asks the human before it runs, on every site: `fox_click`, `fox_type`, `fox_press_key`, `fox_set_value`, `fox_navigate`, `fox_tab` create / close (with or without a container), `fox_handle_dialog` and `fox_interact` hover (it runs the page's own hover handlers; read-only mode refuses it). One approval covers one call of that tool with those arguments on that site; a series of acting calls is asked call by call. Reading, waiting and UI-only tools (`fox_read`, `fox_find`, `fox_screenshot`, `fox_tabs`, `fox_wait`, `fox_interact` scroll / highlight, `fox_tab` switch, …) run without asking. When the daemon has not yet seen the target tab's page, an acting call cannot be approved until `fox_tabs` is called.
- The Firefox extension itself refuses an acting command that was not approved for the site of its tab (or of the URL it opens), whatever the daemon sends.
- The approval prompt (MCP elicitation and the toolbar popup) asks "Allow this operation?" with the tool, the site and the arguments, instead of naming a protected site.
- `fox_safety_status` reports `approvalPolicy` (which calls ask) and `confirmReadSites`, instead of `confirmProtectedActions` and `protectedUrlPatterns`.
- One-time human-approval tokens start with `iat_` (Inari approval token) instead of `kat_`.
- `fox_screenshot` with `scope: "all_tabs"` gives the reason for the tabs it left out on `confirm_read_sites` sites in `excludedReadSitesReason` instead of `excludedReason`, next to `excludedReadSites` and `excludedBlockedReason`.
- `fox_navigate` with `action: "back"`, `"forward"` or `"refresh"` and `newTab: true` acts on the tab as it is, and is approved for the site of that tab (before, the approval was asked for a new blank tab, `about:`).
- `fox_screenshot` with `scope: "scroll_capture"`: `maxScrolls` is at most 50 and `delay` at most 2000 ms, and the extension takes no more steps than fit in 25 s.
- The pause switch also stops a command that is still running: the MCP client gets the `paused` refusal at once, and typing, waiting or `scroll_capture` in the page stops at its next step.
- When the extension cannot read the saved pause switch at startup, it starts paused. When it cannot save the switch, the popup says so (the change then holds until Firefox restarts).
- `fox_request_approval`: at most 3 questions wait in the popup at once; another one is refused at once. The popup shows the approval requests of tool calls before the questions.

### Removed

- The script tools `fox_evaluate` and `fox_observer` (earlier names `fox_execute_script`, `fox_eval_chain`, `fox_wait_and_act`, `fox_inject_observer`, `fox_remove_observer`), on the extension and in headless mode. The extension no longer runs code given as a string (`tabs.executeScript` with `code`).
- The logging tools `fox_logging` and `fox_get_logs` (earlier names `fox_start_logging`, `fox_stop_logging`, `fox_clear_logs`, `fox_get_console_logs`, `fox_get_network_logs`). The extension no longer records the page's console messages or fetch / XHR traffic.
- The `allow_script_execution` key of `safety.json` and the `FOX_ALLOW_SCRIPTS` / `CLAUDE_BROWSER_ALLOW_SCRIPTS` variables. A `safety.json` that still has the key is refused as an unknown key until the key is deleted.
- The `logs` and `script` profiles of `FOX_CAPS` (an unknown profile name is ignored with a warning).
- The "Inspect Element for InariMCP" context menu entry: it handed its result to nobody.
- The protected-site list: `protected_url_patterns` (16 default sites: banks and other finance or payment services, `.gov`, patient portals) and `confirm_protected_actions` in `safety.json`. Acting tools ask on every site instead; list the sites where reads and screenshots should ask as well in the new `confirm_read_sites` (default empty). A `safety.json` that still has either key is refused as an unknown key until the key is deleted.
- The browser commands that no tool sends: `get_tab_info`, `find_tabs`, `get_value`, `reload_all`, `reload_by_url`, `wait_for_change` and `click_and_wait`. Neither the extension nor the headless backend handles them any more.
- The compatibility layer for the earlier tool names of KitsuneMCP: `FOX_CAPS=legacy` (the list with `[Deprecated: …]` descriptions), the 20 earlier names that are no tool any more (`fox_get_text`, `fox_create_tab`, `fox_wait_for_url`, …; refused as unknown tools, also over `POST /mcp/call`), the note on their first call and `legacyTool` in the audit log. Call the 17 tools instead (`fox_read`, `fox_tab`, `fox_wait`, …).
- The never implemented `fox_run_workflow` and `fox_audit_page`, and the empty `workflow` profile of `FOX_CAPS` (now an unknown profile name, ignored with a warning).
- The `CLAUDE_BROWSER_*` environment variables inherited from the fork (`CLAUDE_BROWSER_HOST`, `CLAUDE_BROWSER_HTTP_PORT`, `CLAUDE_BROWSER_WS_PORT`, `CLAUDE_BROWSER_HEADLESS`, `CLAUDE_BROWSER_HEADLESS_STARTUP_TIMEOUT`, `CLAUDE_BROWSER_EXECUTABLE`, `CLAUDE_BROWSER_SCREENSHOTS_DIR`, `CLAUDE_BROWSER_READ_ONLY`, `CLAUDE_BROWSER_SAFETY_CONFIG`): the daemon, the relay, the Native Host, the installer and `--doctor` read only the `FOX_*` names. Also the names `FOX_PORT`, `FOX_DEBUG` and `FOX_CONTAINER`, which nothing read.

### Security

- Values are masked as `[MASKED]` in more fields, on the extension and in headless mode alike: besides password fields, `type="hidden"` fields and fields whose `autocomplete` is `one-time-code` or starts with `cc-` (every payment card field, the card holder's name included; `current-password` / `new-password` as before). In a masked `<select>`, the value and the text of each `<option>` are masked too. `allow_password_typing` still only allows typing into password fields and unmasks nothing.
- The reading tools (`fox_find` by selector, `fox_read` text, `fox_wait` for an element, `fox_interact` scroll / highlight) refuse a CSS selector that tests the `value` or `selected` attribute (such as `[value^="a"]` or `option[selected]`) or uses `:checked` or `:default`, however it is spelled, and one longer than 1024 characters: the match count or the end of a wait could tell a masked value one guess at a time. In headless mode they take plain CSS only (also `fox_snapshot`): `xpath=`, `text=`, `role=`, `//`, `>>` and the other Playwright selector forms are refused.
- `fox_wait` for an element and `fox_interact` (hover, highlight, scroll with `toElement`) return only the tag, generated selector and position of the element, no longer its text, value, link or image address. They are not reads, so `confirm_read_sites` does not apply to them; they used to return the element's text and value, which read a page of such a site without asking.
- With `confirm_read_sites` set, a read of a tab whose URL the extension cannot read is refused instead of allowed, and `screenshot` all_tabs skips such a tab. A `view-source:` or reader view (`about:reader`) tab is matched by the page it shows.
- The daemon refuses to start when `FOX_HOST` is not a loopback address (127.0.0.0/8, `::1`, `localhost`), instead of logging a warning and serving plain HTTP / WebSocket to the network. The native host and the stdio relay refuse such a `FOX_HOST` as well instead of connecting to it, and `--doctor` reports the daemon as not reachable. A host that only looks like an address, such as `127.999.0.1`, is no longer taken as loopback.
- The audit log masks `text`, `value` and the other masked arguments inside nested objects as well (the `option` of `fox_set_value` with `kind: "select"`), and masks the `key` of `fox_press_key`.
- Tools that act on a page are refused on a tab without a host (`view-source:`, `blob:`, `data:`, …; `about:` and `file:` excepted), which no URL pattern of `safety.json` can match. Reading tools still work there.
- A `urlPattern` argument is refused before it is compiled, by the daemon and again by the extension, so one pattern cannot stall the extension's background page: when it is longer than 256 characters; when a repeated group (`*`, `+` or `{…}` after it) holds a quantifier or `|` (such as `(a+)+`, `(a|aa)+`, `(a?){25}`, and also `(a{3})+`: write `(?:aaa)+` instead); when it has more than 7 quantifiers (`*`, `+`, `?`, `{n}`, `{n,m}`, `{n,}`) and `|` together; when a `{n,m}` has m over 32; or when its quantifiers can split a URL in too many ways (an unbounded repeat counts 6, `{n,m}` log2(m − n + 1), `?` and `|` 1, at most 12 in all: `.*.*` is accepted, `.*.*.*` is not). Character classes are read by the JavaScript rules (`[]` and `[^]` end at their first `]`). Ordinary patterns such as `^https://example\.com/.*$`, `https://[^/]+\.example\.com/.*` or `(https?://)?(www\.)?example\.com/.*` are accepted.
- Headless mode checks the approval again right before a command runs, against the page it runs on, as the extension does: an acting command runs only on the site a human approved, and a read of a page in `confirm_read_sites` only with an approval for its site. If the page moved to another site since the approval, the call is asked again for that site.
- `enabled: false` in `safety.json` no longer turns off the human approval in headless mode: every acting tool still asks first, on both backends (it turns off the URL checks and lists, `confirm_read_sites`, `read_only`, `container_scope` and the rate limit).
- Headless `fox_snapshot` shows `[MASKED]` for the value of a masked field (password, one-time code, card number and the others listed above), and does not mark the chosen option of a masked `<select>` as selected. Before, Playwright's accessibility tree showed these values as they are.
- Secret query and fragment parameters (`token`, `access_token`, `password`, …) in URLs are masked in the audit log (`url`) and in the `url` of `details.approval` that the MCP client receives, as they already were in the `url` argument. The approval popup in Firefox still shows the whole URL.
- The extension runs an approved acting command in the page (`fox_click`, `fox_type`, `fox_press_key`, `fox_set_value`, …) only while the tab is still on the origin (scheme, host and port) the approval was checked on. When the tab went elsewhere in between, the command is refused, and the approval is asked again for the page the tab is on now.
