# Changelog

**English** | [日本語](./CHANGELOG.ja.md)

User-facing changes of KitsuneMCP, newest first. Commit hashes are given in parentheses.

## 0.2.0 (2026-10-07)

Changes since 0.1.4. Read **Breaking** before updating, and follow [Update](../README.md#update) in the README.

### Security

- **Request nonces are remembered on a monotonic clock**: the daemon remembers the nonce of each signed request for twice the signature window as measured on a monotonic clock, so setting the system clock forward or back no longer makes it forget a nonce that is still inside the window and accept the same request again. The request timestamp is still checked against the wall clock (34a435c)
- **An unknown key in `safety.json` is a configuration error**: a misspelt or non-existent key (`readonly`, `allow_scripts`, an unknown key inside `container_scope`) used to be dropped without a word, so the setting meant to tighten the policy did not apply. It now refuses every tool like any other broken setting, and the error (in `daemon.log`, `fox_safety_status` and `--doctor`) names the key. See Breaking (4fcbc9f)
- **URL patterns match the parsed URL, and the Extension checks the same way**: `safety.json` patterns are compared with the host (and subdomains), the path and the scheme of the parsed URL, so `example.com.attacker.net` or a query string that mentions a host no longer matches. URLs with a user name or password are refused, and a result whose final URL (after a redirect or a click) is blocked is withheld. Check your lists with `fox_safety_status` after updating (db0e662, b1ebced, 9f5a61d, f8d6496)
- **A broken `safety.json` refuses every tool (fail-closed)**: when the file cannot be read, is not valid JSON, has a wrong type or an unusable URL pattern, every tool except `fox_safety_status` is refused, even with `enabled: false`. Fix the file, restart the daemon and check with `fox_safety_status` (db0e662)
- **Human approval moved out of the page, with one-time approval tokens**: a protected-site action is approved in Claude Code's confirmation dialog (MCP elicitation) or in the toolbar popup, never by buttons in the page, `fox_click` or `fox_execute_script`. An approval covers one call of that tool with exactly those arguments on that host, and the token is seen only by the relay (282ec53, bb005ba)
- **HMAC mutual authentication between the daemon and the Native Host / relays**: the API token is no longer sent; each side proves it holds the token with an HMAC challenge–response, so a program that takes over the port cannot pose as the daemon. A starting daemon whose port is already taken checks the other process's proof, and exits with an error when it is not a KitsuneMCP daemon holding the same token (1de3ecf, 4d2b712)
- **`re:` URL patterns must match the whole URL**: they are anchored as `^(?:<regex>)$`, so `re:example\.com` in `allowed_url_patterns` no longer lets `https://example.com.attacker.net/` through. See Breaking for existing patterns (a015fa5)
- **IPv6 literals and `host:port` in URL patterns**: `[::1]` is read as a host (it used to match every URL containing `:`), and `example.com:8443` matches that port only. An IPv6 address that cannot be parsed, an invalid port or `*.` with an IP address is a configuration error (7ba27cf)
- **Limits on unauthenticated connections and slow request bodies**: at most 8 WebSocket connections may wait for authentication (5 s each, 64 KB before the authentication frame), refused connections are terminated, and an HTTP request body must arrive within 30 s (146fc2d, 2fe3e69)
- **Results cannot be spoofed by an iframe**: commands to a page go to the top frame only, so a frame in the page cannot answer in its place (47d43c6)
- **More secrets are masked in results and the audit log**: credential headers and keys (`x-api-key`, `proxy-authorization`, `accessToken`, …), Basic credentials, `token=` / `password=` in query strings, forms and JSON, and URL fragments are masked; invisible and bidirectional control characters are removed from results (0f0ad33, b1ebced)
- **An empty `container_scope.container_name` is a configuration error**: `"container_name": ""` in `safety.json` used to switch the container scope off without a word; it now refuses every tool like any other broken setting (shown by `fox_safety_status`), whether the scope is enabled or not. Give the container a name (3bb171d)
- **The Extension refuses a command whose safety metadata it cannot use**: a container scope or a URL rule field (protected / blocked / allowed) that the MCP Server attached but that is malformed — not a list, an empty container name — now refuses the command with `config_error` instead of running it without that check. This only happens when the Extension and the MCP Server do not match; update both (3bb171d, f1db501)
- **A URL pattern whose path holds `?` or `#` is a configuration error**: patterns compare the path of the URL only, so `example.com/a?x=1` or `example.com/a#top` matched nothing and, in `blocked_url_patterns` / `protected_url_patterns`, protected nothing without a warning. Such a pattern (also with `%3F` / `%23`) is now an error in every list. Drop the query or fragment, or write the pattern as `re:` (f1db501)
- **Commands from the Native Host must use the wire action names**: an internal action name sent over Native Messaging is answered with `Unknown action` (the Extension's own popup still uses them) (d32eefb)
- **A command's data cannot replace the action the Extension checked**: the Extension builds the message to the page with the checked action last, so an `action` key inside the command's arguments no longer changes which page command runs (469b88e)
- **The safety check keeps track of the tab in more cases**: after a call whose result names no tab (headless mode), the tab id known so far is kept, so a later call with that `tabId` is checked against the page it really shows; a result that reports `tabId` at the top level is followed too. A `fox_tab` `close` the Extension refused (protected site) no longer makes the server forget the tab, and the Extension's own refusals record where the tab is (1452cf8)
- **An error text from the page cannot pose as an approval request**: the text of a failed browser result starts with `Browser error: `, so an error message that is itself JSON is never read as an approval request by the relay (7758f23)
- **A broken `safety.json` is reported before any other refusal**: with a configuration error, a call to a password field or with an invalid `urlPattern` used to be refused for that reason first and logged as `denied`; it is now refused as `config_error` like every other call, and logged as such
- **A refusal the Extension reports with an unknown reason is no silent denial**: the daemon logs a line naming the reason (`daemon.log`) and refuses the call as `denied`. A `config_error` from the Extension (safety metadata it could not use) is logged as `config_error` instead of `denied`
- **Headless `fox_press_key` respects the password guard**: in headless mode a key press is real input, so a character could be typed into a password field one key at a time. On a password field (the element given by `selector`, else the focused one, also inside iframes and shadow roots) every key other than Enter, Tab, Escape, the arrow keys, Home / End, PageUp / PageDown and the modifier keys alone is refused with the same message as `fox_type`, unless `allow_password_typing` is on. The Extension's synthetic key events enter no text and are not affected
- **Password check in XHTML documents**: password fields are recognised in `application/xhtml+xml` pages too, where element names are lower case, by the Extension and in headless mode (there also the control of a `<label>` and the iframes followed for the focused element); they used to be missed there

### Breaking

- **`safety.json` with an unknown key refuses every tool**: check the file with `--doctor` (`safety-config`) or `fox_safety_status` after updating, and correct or remove the key it names. The camelCase spelling of a known key (`readOnly`) is still accepted (4fcbc9f)
- **The in-page approval banner is gone**: approval requests appear as an amber count on the KitsuneMCP toolbar button (plus an OS notification). Open the popup and approve or deny; Claude Code's own confirmation dialog is used first when the client supports MCP elicitation. Reload the extension after updating so the popup is available (bb005ba, 282ec53)
- **`re:` patterns no longer match as a prefix**: a pattern such as `re:^https://example\.com/` stops matching longer URLs, with no warning — in `allowed_url_patterns` those URLs are refused, in the blocked and protected lists they are no longer blocked or protected. Append `.*` to keep the prefix meaning (`re:^https://example\.com/.*`), then check with `fox_safety_status` after a daemon restart (a015fa5)
- **Old-style regular expressions in `allowed_url_patterns` are a configuration error**: simple ones (`paypal\.com`, `^https://a\.example/`) are read as host patterns; any other one makes `safety.json` unusable (every tool refused). Rewrite it as a host pattern or as `re:`. In the blocked and protected lists such a pattern keeps its old meaning, with a warning (db0e662, b1ebced)
- **A daemon from the old version must be stopped**: the daemon, the relays and the Native Host now authenticate with HMAC and check the protocol version, and an old Native Host's plain token is refused. When the relay or the Native Host reports that the running daemon "speaks protocol …" / "is from another version", stop that daemon process (restart Firefox if the Native Host started it) and reload the extension; the next tool call starts a matching daemon (1de3ecf, 7ba27cf)
- **`install.ps1` / `install.sh` / `uninstall.ps1` / `uninstall.sh` are replaced by `npm run setup` / `npm run teardown`**: the Node.js installer needs no PowerShell and does not build unless asked. Run `npm ci`, `npm run build`, then `npm run setup` (or `npm run setup -- --build`); `npm run install:*` / `uninstall:*` remain as aliases. For manual setup, the manifest template is now `packages/native-host/kitsune_mcp.json` and `run-host.cmd` / `run-host.sh` are no longer in the repository: `node scripts/install.mjs --manual` prints the steps (5b8645f, fae166b)
- **`FOX_HEADLESS` is on only for `1`, `true` or `yes`**: `FOX_HEADLESS=0` or `false` used to turn headless mode on. Remove the variable or set `0` to use the extension path. `FOX_READ_ONLY` now also accepts `true` / `yes`, and `FOX_ALLOW_SCRIPTS` accepts `false` / `no` / `off` (2e9ab03, dcf7bfa)
- **`fox_type` no longer uses `text` to find the element, and `pressEnter` submits the form**: the text to type is never used as a locator. Pass `selector`, `xpath`, `placeholder`, `name` or `id`, or leave them out to type into the focused element. `pressEnter` (and `fox_press_key` Enter) submits the form the way a real Enter does (47d43c6)
- **Headless `fox_snapshot` and `fox_scroll` changed**: `fox_snapshot` returns the accessibility tree as YAML text (with `maxDepth`, `includeText`, `roles`) instead of a base64 screenshot; use `fox_screenshot` for an image. `fox_scroll` follows `direction`, `amount`, `selector` and `toElement` instead of always scrolling 300 px down (208cb30)
- **Tool classes are derived from the tool schemas**: `fox_remove_observer` is a script tool and is refused when script execution is off. `fox_hover`, `fox_scroll`, `fox_highlight` and `fox_switch_tab` are class `interact`: they work in read-only mode and on protected sites without approval, and their `readOnlyHint` is `false` (7febaa5)
- **Every package reports version 0.1.4**: the daemon, relay and Native Host used to report 0.1.0 while the extension was 0.1.4; all `package.json` files and the manifest now have the same version, which `--doctor` checks. Update all parts together (c9cbd41)
- **The 41 tools are now 21, and a session lists the new names**: prompts or settings that name an earlier tool need the new name, or `FOX_CAPS=legacy`. The earlier names still work when called. See [Tool names (41 → 21)](#tool-names-41--21) (59dee5c, 00bca2b)
- **`fox_navigate` takes `url` with `goto` only**: `goto` (the default action) without a `url` is refused, and so is `back`, `forward`, `refresh` or `hard_refresh` with a `url`. Such a `url` was not used, but the safety check took it for the destination and did not check the tab the call acted on. Leave `url` out of those calls (7758f23)
- **Numeric arguments have a lower bound**: `limit`, `maxLength`, `pollIntervalMs`, `timeout` of `fox_evaluate` `wait_and_act`, `duration`, `maxScrolls` and `scrollStep` must be at least 1; `amount`, `idleTime`, `delay` and the option `index` of `fox_set_value` `select` at least 0. Smaller values are refused as invalid arguments (7758f23)
- **Failed browser results start with `Browser error: `, and the audit log records them as `browser_error`**: a program that reads tool results or the audit log and looked for the old text or the `denied` line must be updated. See Security (`Browser error: `) and Fixed (one audit line per call)
- **Headless `fox_type` with `selector` appends, as on the Extension**: the text is added after the field's current content; pass `clear: true` to replace it (the `clear` warning is now given only without `selector`)
- **Headless `fox_read` `mode: "text"` reports `totalLength` and `title`**: the key `total_length` is gone, as on the Extension
- **Headless `fox_interact` `action: "scroll"` without `direction` moves nothing**: it used to scroll down; like the Extension it now returns `scrolled: true` and the position. A `selector` that matches nothing scrolls the window, and a `toElement` that matches nothing falls through to `direction` (both with a warning) instead of failing

### Tool names (41 → 21)

Related operations became one tool with a mode argument (a discriminator key such as `mode`, `action` or `kind`). The browser side did not change: each call of a new tool runs what the earlier tool ran. Details in [Tool name migration](../README.md#tool-name-migration) in the README (93054cc, 00bca2b, 59dee5c, 7713270, c4bd216).

- **`tools/list` lists the 21 new tools by default**: with `FOX_CAPS` unset, `all` or any profile, a session lists the new names. `FOX_CAPS=legacy` (alone, or with profiles: `legacy,core`) lists the 41 earlier tools and their earlier profiles instead; the 28 replaced tools and the 2 to be removed start their description with `[Deprecated: …]`. `fox_safety_status` is always listed (59dee5c, 93054cc)
- **Earlier names keep working**: the daemon accepts both names whatever `FOX_CAPS` says, also over HTTP (`POST /mcp/call`). The first call of each earlier name in a process ends its result with a `Note:` naming the replacement (`fox_get_text is deprecated; use fox_read with mode='text'.`) and writes the same to stderr (`daemon.log`); later calls of that name get no note (00bca2b)
- **The audit log records the new name**: a call of an earlier name is logged with `tool` = the new name and `legacyTool` = the earlier name (93054cc)
- **Approval is bound to the name as called**: the approval request and the token check hash the called name and the call arguments, so retry with the same name and arguments as the approved call (93054cc)
- **Tool results are compact JSON**: successful results, the metadata of `fox_snapshot` and the result of `fox_safety_status` are JSON without indentation (7713270)
- **Messages use the new names**: tool descriptions are shorter, and the approval guidance, the headless warnings and the Extension's errors name the new tools (c4bd216)

### Added

- **`--help`, `--version` and `--doctor`**: `node packages/mcp-server/dist/index.js --doctor` checks 14 items (build, Firefox and Claude Code registration, daemon, token, logs, …) read-only and prints a fix for each problem; it exits with code 1 when an item FAILs. A missing `native-messaging` registration is a WARN (exit code 0: the extension route needs it, headless alone does not), a broken one (invalid JSON, wrong name, type, allowed extension or path) is a FAIL, and the fixes point to `npm run setup`. `--help` / `--version` exit before a daemon, token or log is created. An unknown argument now exits with code 2 instead of starting a relay (5afc516, 0e06a30, 7a4e61f)
- **`--stop-daemon`**: `node packages/mcp-server/dist/index.js --stop-daemon` stops the running daemon over a signed `POST /daemon/shutdown`: running tool calls get up to 10 s to finish (`--force`: none), headless Firefox is closed and the Native Hosts are disconnected (WebSocket close 1001) before it exits. `npm run teardown` and the doctor's fixes use it; the uninstaller sends a signal only without the API token or when that request fails
- **`FOX_APPROVAL_ELICITATION`**: set `0` / `false` / `off` / `no` to approve protected-site actions in the Firefox popup only (headless mode then cannot approve). It is on by default (4a785bb)
- **`FOX_SCREENSHOT_RETENTION_DAYS`** (default `30`): at each Native Host start, screenshots saved under a generated name and older than this many days are deleted. Set `0` to keep everything; files saved under your own `filename` are never deleted (69b1af9)
- **Logs survive reloads and navigations**: console and network logs are kept per tab in the Extension's background (latest 500 of each), so `fox_get_console_logs` / `fox_get_network_logs` return entries from before a navigation (47d43c6)
- **Timestamps in `daemon.log`**: each line starts with `<ISO 8601 time> [<pid>] `, like `native-host.log` (7b03a8f)
- **Headless mode lists ignored parameters**: parameters the headless backend does not support are reported in the result's `warnings` (in `error` on failure) (208cb30, 59597b6)
- **`playwright` is optional**: the relay and the extension-path daemon start without it; a `FOX_HEADLESS` daemon without it exits with a message that explains how to install it. `npm run build` still needs it (1cf3974, 2e9ab03)
- **End-to-end smoke tests**: `npm run test:e2e` drives relay → daemon → headless Firefox over MCP with a temporary home directory and free ports, and `npm run e2e:extension` checks that the extension loads into Firefox (2bd20a0)
- **`@kitsune-mcp/shared/node`**: the Node.js helpers of the daemon, relay and Native Host (paths, endpoint, token, `/health`, logs, daemon start, version, HMAC) in one subpath; the package root stays browser-safe (9896141)
- **`GET /mcp/tools` lists the safety classes as a list**: each tool has `classifications` (for example `["act", "interact"]`) next to the `|`-joined `classification`, which is unchanged

### Fixed

- **Daemon shutdown and start-up failures**: once the daemon begins to stop (`--stop-daemon`, a signal or the idle timeout), new tool calls and approvals are answered "shutting down" (HTTP 503) and not run; the relay then waits for that daemon to exit and sends the call once more, to a new daemon. SIGTERM or SIGINT during a graceful stop ends the wait for running calls at once. A shutdown that fails is answered with HTTP 500 and the daemon exits anyway, instead of staying behind and refusing every call. When the headless browser cannot start, tool calls already waiting get the reason (HTTP 500) before the daemon exits (cd70735, 55e93f7)
- **Relay approvals and refused signatures**: when the daemon has MCP elicitation turned off, an action the human approved in Claude Code's dialog is asked again in the toolbar popup (a denial stays a denial). When the daemon still refuses this session's signature after the token was read again, tool calls, approvals and `--stop-daemon` all give the same message telling you to stop the daemon. `fox_safety_status` adds a note when the daemon's settings could not be read, and checks them again on the next call (55e93f7)
- **Configuration and approval texts**: a partial `container_scope` in `safety.json` (only `container_name`, or only `enabled`) takes the default for the rest instead of refusing every tool. A blank `FOX_SAFETY_CONFIG` / `FOX_SCREENSHOTS_DIR` counts as unset in the daemon and `--doctor` (the legacy name is read), and a relative `FOX_SCREENSHOTS_DIR` is made absolute as the Native Host does. Approval request summaries are cut without splitting an emoji. The warning for a single-label host pattern (`intranet`) is also given for `LOCALHOST`, `intranet/`, `intranet:8080` and `http://intranet` (4fcbc9f, c54bfe2, 176858f, 71aafd0)
- **Native Host start-up**: the host answers `ping` while it is still starting the daemon, and on Windows it starts the daemon outside Firefox's job object without PowerShell when needed (WMI, then `schtasks`), so closing Firefox does not stop the daemon. `daemon.log` is rotated with copy-truncate, because the running daemon keeps it open (82172be, c1521e9, 6856992, 099da45, 69b1af9)
- **Headless backend**: `fox_select_option` fails with `availableOptions` when no option matches, `fox_handle_dialog` no longer blocks other commands (a dialog nobody waits for is dismissed after 2 s and reported), and `FOX_HEADLESS_STARTUP_TIMEOUT` is applied to the Firefox launch (208cb30, 36cb870, 2e9ab03)
- **Headless commands end within the server's wait, and closing the last tab is no longer fatal**: a command whose call timed out or was cancelled while it waited for an earlier one is not run any more; a second `fox_handle_dialog` on the same tab replaces the first instead of leaving it armed; `fox_evaluate` scripts, each `chain` step and each `wait_and_act` condition / action are given up after 30 s or when the call ends; `wait_and_act` reports the measured `elapsed_ms` (a `pollIntervalMs` of 0 or less, which only a command that bypasses the tool schema can send, polls every 200 ms); the element waits of `fox_type` / `fox_set_value` / `fox_interact` `hover` / `fox_press_key` and the page loads of `refresh` / `fox_tab` `create` have timeouts of their own, and a tab whose `create` load fails is closed. After the last tab is closed, `fox_tabs`, `fox_tab` `create` and `fox_navigate` with `newTab: true` still work and other tools say how to open a tab. Successful results carry the `tabId` and current `url` of the tab they ran on (cdcbd04, 2a2793c, a6f6a33)
- **Headless arguments are checked, `get_value` masks passwords, a blank `FOX_EXECUTABLE` is unset**: the headless backend reads arguments as the tool schemas deliver them and fails on anything else. A `scroll` `direction` other than `up` / `down` / `left` / `right` / `top` / `bottom` fails instead of being ignored (the tool schema already refuses it, so only a command that bypasses it is affected). The headless `get_value` command returns `[MASKED]` for a password field, as the Extension does (no tool sends `get_value` today). A blank `FOX_EXECUTABLE` counts as unset, so the legacy name or Playwright's Firefox applies (107cf40, f35589e, be3453e)
- **The relay no longer waits for the daemon before connecting**: Claude Code's MCP connection returns at once; the first tool call waits for the daemon to start (81294f6)
- **Settings differences are compared after normalisation**: `true` / `1` and old / new variable names count as the same, so the "different settings" warning no longer appears for equivalent values, also against an older daemon (dcf7bfa, f6ad469)
- **`allow_password_typing` reaches the Extension**: password fields are judged by one rule on the server, the Extension and headless mode, which also covers `fox_set_value`, `xpath` and `autocomplete` `current-password` / `new-password` (4b070f5)
- **Read-only mode and the rate limit count the right calls**: `fox_switch_tab` and `fox_detect_captcha` are no longer refused in read-only mode, and refused calls and `fox_safety_status` no longer count toward the rate limit (7febaa5, 354730c)
- **Extension tools report failures**: `fox_wait_for_network_idle` fails on timeout, `fox_select_option` fails when no option matches, `fox_click` / `fox_type` fail on disabled elements, and page loads that time out or whose tab closes fail. `fox_type` accepts `delay: 0` and keeps all delays within 10 s (47d43c6)
- **Screenshots**: `fox_screenshot` with `all_tabs` has a time budget and fails when no tab could be captured or saved, `saveToFile: false` captures nothing, and saving under an existing `filename` adds `imageOverwritten` and a warning (47d43c6, e3cb939)
- **Cancelled calls stop the browser command**: request IDs are unique per daemon start, and cancelling a tool call fails the pending browser command (4f2fb52)
- **Extension: tab commands and the Native Host connection are steadier**: reloading several tabs at once (the Extension's `reload_all` / `reload_by_url` commands) reloads every tab even when one fails, and reports the failed tabs with `reloaded: false`, `error` and `failedCount`; it fails only when no tab could be reloaded. `fox_wait` `for: "navigation"` succeeds when the tab closes right after the page loaded. `fox_tabs` with a `limit` of 0 or less uses the default (50), and `fox_find` `by: "text"` with an empty `text` fails with a clear error. After a failed send, a late disconnect report of the old connection no longer drops the new one, and an older setup check no longer puts a stale "!" on the toolbar badge (eddccfd, bd09818)
- **Extension popup and approvals**: when the background does not answer, the popup shows an error with the reason instead of staying at "Connecting...", and its buttons and approval list still work when the current tab cannot be read. An approved action is accepted on its host written with a trailing dot (`example.com.`). Long texts in approval requests, notifications and logs are cut without splitting an emoji (bd09818)
- **`fox_interact` `highlight` keeps the newest highlight**: the removal timer of an earlier highlight no longer removes a later one early (the context menu's "inspect element" too). In the Extension, a captcha wait banner replaced by a newer one in the same tab ends at once (`superseded: true`), and a banner closed because the captcha token arrived is no longer reported as cancelled by `cancel_human_wait` (a59434a)
- **Extension commands reject unknown values and keep more in the logs**: `fox_interact` `scroll` with an unknown `direction` fails instead of reporting `scrolled: true`; the Extension's change wait fails when its `selector` matches nothing (instead of watching the whole page) or its `changeType` is unknown. Generated `fox_inject_observer` ids no longer repeat within a millisecond (a repeated id replaced the earlier observer). The network log records XHR requests that were aborted (`error: "Aborted"`) or timed out (`error: "Timeout"`). Texts cut to a length limit (element texts and values, `fox_get_text`, console and network logs) no longer split an emoji or another character outside the BMP, and element values that are numbers (`<li value>`) no longer fail element listings (eb227e7)
- **Extension: `fox_read` `mode: "info"` explains a page it cannot reach (changed error text)**: on a page without the Extension's content script it used to fail with Firefox's own `Could not establish connection. Receiving end does not exist.`; it now fails with the same text as the other page tools, `KitsuneMCP cannot reach this page: Firefox does not let extensions into it (JSON viewer, about: pages, addons.mozilla.org, other extensions' pages), or it was opened before KitsuneMCP was installed or updated (reload the tab). Tab-level tools such as fox_screenshot and fox_tabs still work.` Other failures keep their text (e330de3)
- **Extension: a send that fails on every retry no longer leaves a broken connection**: when posting to the Native Host still fails after the last retry, the broken connection is closed and the Extension reconnects on the usual backoff, instead of keeping it until a disconnect report that may never come. Generated `fox_inject_observer` ids are now `obs_<time>_<number>` (the random suffix is gone; the number keeps them unique in the page) (14d75ee, 725bdda)
- **Empty token file**: an empty or unreadable `~/.kitsune-mcp/api_token` is no longer overwritten: the daemon exits with a message to delete it (5cf492a)
- **The Native Host's restart limit is a real limit**: after 10 failed daemon starts the Native Host stops trying until a usable daemon appears, instead of starting it again on every check. A screenshot `data:` URL with a MIME type other than PNG, JPEG or WebP is refused (b82e98d)
- **Uninstaller and installer messages**: an unreadable or broken `~/.claude.json` / `.mcp.json` is reported as a problem (exit code 1) instead of "not registered", and a Firefox registration that points to another checkout is reported with a warning. Paths in `--help` and `--manual` output are quoted, the daemon check commands the installer and `--help` print (`curl` /health, port lookup) use the configured host and port, and a path containing `%` is refused where it would be passed to `cmd` (d04e56a)
- **The audit log has one line per call, and `audit_log: false` writes none**: a call that ran used to be logged twice (`allowed` by the safety check and again after the browser answered), even with `audit_log: false`, and a call that failed in the browser was logged as `denied`. Now the safety check's line stands alone, a failure in the browser adds a `browser_error` line, and `allowed_by_human` is logged only when an approval lifted a confirmation. A password field or an invalid `urlPattern` is refused before the safety check, so it no longer counts toward the rate limit or leaves an `allowed` line (a refused password field is logged as `denied`). A call by an earlier tool name is logged with the arguments the new tool would have parsed (its mode key, renamed arguments and defaults), as for a call by the new name (1452cf8, 7758f23)
- **An approval token that did not help is reported**: when a call with an approval token still needs confirmation (the token is for another site, say), the result says the token was not accepted and that the human is asked again when the call is retried (7758f23)
- **`fox_safety_status` names the configuration file that was read**: `configFile` is the full path the daemon loaded; a blank `FOX_SAFETY_CONFIG` counts as unset there too (1452cf8)
- **`fox_handle_dialog` no longer says it is in no `FOX_CAPS` profile**: the public tool is in the default list; the earlier description is kept for `FOX_CAPS=legacy` (7758f23)
- **`fox_navigate` with `newTab` and a `tabId` no longer records the new page for the named tab**: the safety check kept the new tab's URL as the URL of the tab given by `tabId`, so later calls on that tab were checked against the wrong page
- **The details of a safety refusal always name its layer**: `details.layer` is set for every refusal of the safety check (it used to be set only for refusals the Extension made); a configuration error has none
- **Headless backend matches the Extension in more tools**: `fox_set_value` sets a `<select>` (value, then `input` and `change`); `fox_find` `by: "text"` counts the occurrences in the page text, honours `caseSensitive` and `entireWord`, takes quotes and backslashes as plain text and refuses an empty query; `fox_find` `by: "selector"` returns `count` (every match) and honours a `limit` up to 50; `fox_get_value` reads a `<label>` and other non-field elements as their text and a `<select>` as its selected value; `fox_select_option` by text also matches the trimmed option text; `fox_interact` `highlight` keeps the outline for `duration`; `fox_wait` `for: "element"` honours `visible: false`, and `for: "navigation"` honours `waitUntil`; `fox_press_key` also reports `pressed`
- **Headless waits end when the caller gives up**: `fox_wait` (element, network idle, navigation, URL) stops at the caller's deadline and ends at once on cancellation, so the next command no longer waits until the wait's own timeout
- **Headless `fox_wait_and_act` says why it failed**: when the condition is never met, the error names the last error the condition threw, and says when the caller's deadline ended the wait before `timeoutMs`
- **`FOX_*` settings are read without surrounding white space**: e.g. `FOX_EXECUTABLE` with a trailing space or newline is used as the path without it
- **A blank `FOX_HOST` / `FOX_HTTP_PORT` / `FOX_WS_PORT` counts as unset**: the daemon, the relays, the Native Host and the installer / uninstaller take an empty value or one of only spaces as not set (the legacy `CLAUDE_BROWSER_*` name, then the default, applies) and use a set value without its surrounding spaces, like every other `FOX_*` variable. `FOX_HOST=' '` used to be passed on as the address, so the daemon could not listen and the Native Host could not reach it; a blank port no longer logs an "ignoring … not a port number" warning. The installer and uninstaller read `CLAUDE_CONFIG_DIR`, `XDG_CONFIG_HOME`, `ComSpec`, `PATH` and `PATHEXT` the same way
- **The uninstaller recognises the daemon as `/health` does elsewhere**: an answer is taken as a KitsuneMCP daemon only with `status: "ok"`, the same test the relays and the Native Host use
- **Installer / uninstaller output errors**: an error writing to stdout other than a closed pipe is reported in one line and exits with code 1, instead of a stack trace
- **A tool answer that cannot be written is answered 500**: when the daemon could not serialize a tool or approval result, the request stayed open without an answer until the relay timed out (and the error went unhandled). It now answers HTTP 500 with the reason and writes it to `daemon.log`
- **`--doctor` compares the daemon settings the way the relay does**: the `settings` item compared the raw variable values, so `FOX_READ_ONLY=true` against `1`, or an old `CLAUDE_BROWSER_*` name against its `FOX_*` name, was a WARN although the relay treats them as the same. It now compares the effective values with the relay's own rule, and the WARN reads like the relay's warning (`FOX_READ_ONLY: this session 'on', daemon 'off'`)
- **The relay waits longer when the headless startup timeout is raised**: the relay's wait for the daemon's answer was the longest command timeout plus a fixed 60 s, which a `FOX_HEADLESS_STARTUP_TIMEOUT` above 45 s could exceed. The margin is now that startup timeout plus 15 s (60 s with the default)
- **Messages name the real file locations**: the relay's "no API token" / "daemon unavailable" messages and `--doctor`'s `logs` item build the `api_token` and log paths from the data directory instead of a fixed `~/.kitsune-mcp/...` text. The request size limit in the relay's message is the daemon's own value (in bytes)
- **`fox_scroll` result in the Extension**: `amount: 0` scrolls 0 pixels instead of the 300 px default, and `position` is always the measured `{ x, y }` after the scroll — also for `top` (it was always `{ 0, 0 }`), `bottom` (it was the string `"bottom"`) and `toElement` (it had none). A `selector` or `toElement` that matches nothing and a call without `direction` behave as before
- **Waiting for a text change**: `wait_for_change` with `changeType: "text"` now sees changes of a text node; it always ran into its timeout
- **`fox_observer` `inject` in the Extension records text changes**: a change of a text node inside the observed element failed in the observer, so it and the other changes of the same batch were lost; it is now recorded with the selector of the text's parent element
- **Native Host connection status**: when sending to the Native Host fails, the Extension reports the reason (popup / `status`) and restarts the reconnect backoff after a stable connection, as it does when the host disconnects. A malformed message from the Native Host is dropped instead of being taken as an answer or a command
